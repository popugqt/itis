# Задача: оформление Markdown-документа в заданном стиле

Я отправлю тебе готовый текст доклада, конспекта или учебного материала. Твоя задача - **только отформатировать его**, приведя к единому стилю оформления, описанному ниже.

Не переписывай материал заново, не сокращай его, не меняй смысл и не удаляй важную информацию. Сохрани все определения, формулы, примеры, решения, таблицы, пояснения и последовательность изложения.

Тебе необходимо сделать текст удобным для чтения и изучения в Obsidian.

---

## 1. Общий стиль оформления

Используй Markdown и LaTeX.

Основные правила:

- Пиши простым и понятным русским языком
- Сохраняй учебный, последовательный стиль изложения
- Разбивай большие разделы на небольшие подразделы
- Используй горизонтальные разделители `---` между крупными частями
- Определения сначала выделяй, затем объясняй простыми словами
- Алгоритмы оформляй нумерованными списками
- Примеры оформляй отдельными подразделами
- Для сравнений и структурированных данных используй таблицы
- Для важных замечаний используй цитаты Markdown
- Не перегружай текст выделениями
- Не используй эмодзи без необходимости

Не превращай весь документ в сплошной текст. Он должен быть структурированным, как хороший учебный конспект.

## 2. Цветовое оформление

Для выделения текста используй HTML-теги:

`<span style="color: ...">`

`<span style="background-color: ...">`

Не используй другие способы раскрашивания текста.

### 2.1. Заголовки

Все заголовки, например:

`# Классы Поста: проверка с обоснованием каждого знака`

`## 1. Основные определения`

`### Пример 1. Проверка функции`

Должны иметь только изменённый задний фон.

Цвет фона:

`rgba(213, 142, 173, 0.30)`

Пример:

`# <span style="background-color: rgba(213, 142, 173, 0.30);">Классы Поста</span>`

**Важно:** не изменяй цвет текста заголовков. У них должен быть только фон.

### 2.1.1. Заголовки с математическими формулами

Если внутри заголовка используется математическая формула, действуют два случая:

- **Формула в середине заголовка** - заголовок **не оборачивается** в `<span>`, чтобы формула корректно отображалась. Фон у такого заголовка не задаётся
- **Формула слева или справа от текста заголовка** (но остаётся внутри заголовка) - в `<span>` оборачивается только текстовая часть, а формула остаётся снаружи

Шаблон для второго случая:

`## <span style="background-color: rgba(213, 142, 173, 0.30);">Title</span> $Math$`

Примеры:

- Формула в середине (фон не задаётся):

  `### Число $e$ как предел числовой последовательности`

- Формула справа от текста (в `<span>` только текст):

  `### <span style="background-color: rgba(213, 142, 173, 0.30);">Число</span> $e$`

- Формула слева от текста (в `<span>` только текст):

  `### $e$ <span style="background-color: rgba(213, 142, 173, 0.30);">как предел</span>`

### 2.2. Определения и термины

Используй цвет текста:

`#D58EAD`

Выделяй:
- Определения
- Названия математических понятий
- Названия методов и алгоритмов
- Специальные термины
- Важные названия объектов

Примеры:
- Импликанта
- Простая импликанта
- Тупиковая ДНФ
- Сокращённая ДНФ
- Полином Жегалкина
- Самодвойственность
- Монотонность
- Полнота системы
- Базис
- Литерал
- Конъюнкт

Пример оформления:

`<span style="color: #D58EAD;">Простая импликанта</span> - это импликанта, из которой нельзя удалить ни один литерал, не потеряв её свойство быть импликантой`

Не окрашивай целые абзацы, если достаточно выделить само понятие.

### 2.3. Действия, количества и опорные моменты

Используй цвет текста:

`#AE91CE`

Выделяй:
- Количество действий и объектов
- Порядок выполнения
- Условия и ограничения
- Важные промежуточные действия
- Места, на которые нужно обратить внимание при решении
- Слова, определяющие ход алгоритма

Примеры:
- одну
- две
- несколько
- каждый
- только один
- в каждом столбце
- после удаления
- повторяем
- проверяем
- необходимо найти

Пример:

`Удаляем <span style="color: #AE91CE;">один</span> литерал и проверяем получившийся конъюнкт`

### 2.4. Запреты, неудачи и отрицательные результаты

Используй цвет текста:

`#e0313a`

Выделяй:
- Запреты
- Невозможные действия
- Ошибочные результаты
- Неудачные попытки
- Отрицательные выводы

Примеры:
- нельзя
- не является
- не принадлежит
- невозможно
- не подходит
- не получается
- функция равна 0 в неподходящем наборе

Пример:

`Удалять этот литерал <span style="color: #e0313a;">нельзя</span>, поскольку полученный конъюнкт перестаёт быть импликантой`

### 2.5. Успешные действия и положительные результаты

Используй цвет текста:

`#8FBF8F`

Выделяй:
- Успешные действия
- Полученные правильные результаты
- Подтверждённые свойства
- Положительные выводы

Примеры:
- является импликантой
- принадлежит классу
- система полная
- получаем
- подходит
- успешно склеивается
- следовательно, условие выполнено

Пример:

`Следовательно, полученный конъюнкт <span style="color: #8FBF8F;">является импликантой</span>`

### 2.6. Важные замечания

Для слова «Важно!» и действительно важных предупреждений используй фон:

`rgba(224, 108, 117, 0.28)`

Пример:

`<span style="background-color: rgba(224, 108, 117, 0.28);">**Важно!** Нельзя пропускать проверку каждого литерала</span>`

Не выделяй этим фоном обычные объяснения. Используй его только для существенных замечаний, исключений и предупреждений.

## 3. Использование цитат

Не забывай использовать цитаты Markdown через символ `>`.

Цитаты нужны для визуального отделения:
- Определений
- Основных правил
- Теорем
- Важных выводов
- Пояснений к формулам
- Особых случаев и исключений

Пример:

> **Импликанта** - конъюнкт, который обращает функцию в единицу на всех наборах, где сам конъюнкт равен единице

Ещё пример:

> **Важно!**  
> Для доказательства того, что конъюнкт не является импликантой, достаточно привести один контрпример

Не оформляй цитатой абсолютно каждый абзац. Используй её там, где она действительно помогает выделить смысл.

Не выдумывай авторские цитаты, источники или ссылки. Если в исходном документе есть цитаты с указанием автора или источника, сохрани их без изменений.

## 4. Оформление формул

Для математических выражений используй LaTeX.

Внутри текста (строчная формула):

`$f(x)=x_1\land x_2$`

Отдельная формула (блочная формула):

`$$f(x)=x_1\land x_2$$`

Перенос строки внутри блочной формулы - `\\`:

`$$a+b=c\\d+e=f$$`

Правила:
- Не заменяй математические символы обычными буквами
- Не повреждай существующие формулы
- Не удаляй индексы и степени
- Используй `\boxed{}` для итоговых ответов и важных результатов
- Используй `\begin{cases}` для систем уравнений
- Сохраняй корректную математическую запись
- Строчные формулы оборачивай в `$...$`
- Блочные формулы оборачивай в `$$...$$`
- Перенос строки внутри формулы оформляй через `\\`

Если формула в исходном документе написана некорректно, не исправляй её наугад. Сохрани исходную запись и сообщи о проблеме отдельно.

## 5. Оформление примеров и решений

Каждый пример должен иметь понятную структуру.

Рекомендуемый шаблон:

### Пример 1. Название примера

Дано:

`$$f(x_1,x_2)=x_1\oplus x_2$$`

**Решение**

1. Сначала выполняем первое действие
2. Затем показываем промежуточный результат
3. Объясняем, почему выполняем следующее действие
4. Получаем итоговый ответ

**Вывод**

`$$\boxed{f(x_1,x_2)=x_1\oplus x_2}$$`

Не пропускай промежуточные вычисления, если они необходимы для понимания решения.

Если в таблице есть знаки `+` и `-`, каждый знак должен быть обоснован. Нельзя просто поставить знак без объяснения того, почему функция принадлежит или не принадлежит соответствующему классу.

## 6. Правила пунктуации и тире

**Это обязательные правила, соблюдай их во всём документе.**

### Тире

Вместо длинного тире `—` всегда используй короткое тире `-`.

Не используй длинное тире даже в заголовках, определениях и пояснениях.

### Точки

Не ставь точку в конце строки, абзаца, пункта списка, формулы или цитаты, если после них идёт пустая строка либо заканчивается соответствующий блок.

Ставь точку только тогда, когда после неё сразу продолжается следующее предложение в том же абзаце, без пропуска строк.

Пример правильно:

`Импликанта - это конъюнкт, который обращает функцию в единицу`

`Если хотя бы на одном наборе функция равна нулю, конъюнкт не является импликантой`

Пример с точкой:

`Сначала составляем таблицу значений функции. Затем проверяем каждый набор`

То есть:
- В конце самостоятельного абзаца точку не ставить
- В конце пункта списка точку не ставить
- После отдельной формулы точку не ставить
- В конце строки таблицы точку не ставить
- Между двумя предложениями одного абзаца ставить точку
- Не добавлять точки просто ради единообразия

## 7. Сохранение исходного содержания

Это одно из самых важных требований.

Ты выполняешь именно форматирование, а не редактуру содержания.

Запрещено:
- Сокращать исходный материал
- Удалять примеры
- Удалять пояснения
- Менять математические решения
- Самостоятельно придумывать новые определения
- Изменять смысл предложений
- Подменять исходные формулы другими
- Добавлять неподтверждённые факты
- Переставлять разделы без необходимости

Разрешено:
- Исправлять очевидные опечатки
- Исправлять Markdown-разметку
- Исправлять визуально повреждённые обозначения, если правильный вариант однозначен
- Разбивать слишком большие абзацы
- Добавлять заголовки для уже существующих смысловых разделов
- Выделять ключевые слова и определения
- Оформлять уже имеющиеся правила в виде цитат
- Преобразовывать обычные перечисления в таблицы, если так информация воспринимается лучше

Если обнаружишь математическую ошибку или неоднозначность, не исправляй её молча. Сохрани исходное содержание и перечисли обнаруженные проблемы отдельно после документа.

5. При заголовках с формулами соблюдай правило из раздела 2.1.1
6. Добавь цитаты там, где это уместно
7. Приведи формулы к корректному LaTeX-оформлению, не меняя их смысл: строчные - `$...$`, блочные - `$$...$$`, перенос строки - `\\`
8. Соблюдай правила тире и точек
9. Проверь документ на пропущенные разделы и повреждённые формулы

**Не присылай мне рекомендации по оформлению вместо результата. Мне нужен сам готовый документ.**
